# Work timeline (reconstructed)

This is a coarse reconstruction from the retained conversation and repository contents on 2026-10-20. Exact timestamps, every prompt, and intermediate experiments were not preserved, so this is not a complete activity log.

1. The checkout brief and an initial implementation plan were reviewed. The first product implementation is recorded in [the initial checkout commit](https://github.com/FirasAyari/self-service-checkout/commit/89ad3e8); the timeline and exact prompt sequence are retrospective, not a preserved session transcript.
2. The updated implementation plan selected a .NET 10 Minimal API, EF Core/SQLite, and a React/Vite client. The stack choice and its status as an allowed preference deviation are recorded in [ADR-0001](adr/0001-dotnet-api-react-client.md).
3. ECC review passes covered business/domain rules, .NET architecture and build repair, payment/security boundaries, and accessibility. The resulting decisions and caveats are recorded in [the plan review](plan-review.md) and [AI workflow](ai-workflow.md).
4. The solution was separated into Domain, Application, SQLite Infrastructure, Contracts, and HTTP host projects through a sequence of commits: [solution organization](https://github.com/FirasAyari/self-service-checkout/commit/4a4c6ee), [domain rules](https://github.com/FirasAyari/self-service-checkout/commit/2464f2d), [application workflows](https://github.com/FirasAyari/self-service-checkout/commit/d6a8ba1), [SQLite transactions](https://github.com/FirasAyari/self-service-checkout/commit/bfabf2a), and [HTTP endpoints](https://github.com/FirasAyari/self-service-checkout/commit/fa329e6). The user-profile SDK installation is environment setup, not a repository dependency.
5. Backend tests and the broader verification harness were added in [the backend test commit](https://github.com/FirasAyari/self-service-checkout/commit/ebae5b1) and [the verification harness commit](https://github.com/FirasAyari/self-service-checkout/commit/b134a5e). Their present coverage is measured by `make trace` and named test evidence, not inferred from this timeline.
6. The React kiosk client, container, and CI were added in [the frontend commit](https://github.com/FirasAyari/self-service-checkout/commit/6ab6c94), [the Docker commit](https://github.com/FirasAyari/self-service-checkout/commit/348aac3), and [the CI commit](https://github.com/FirasAyari/self-service-checkout/commit/30e3b7d). Delivery and architecture checks were added in follow-up commits.
7. The OpenAPI snapshot/type generation and drift checks were added. Demo chaos now covers bounded latency and lost-response recovery alongside decline and ambiguous outcomes. Cold-brew size/add-on pricing and an offline QR receipt were completed from the P2 scope. The scope and trade-offs are recorded in [the ADR index](adr/README.md), [plan review](plan-review.md), and [rejected decisions](rejected.md).

For exact present-state evidence, inspect source, test output, `docs/traceability.md`, and `git` history. This reconstructed timeline should not be extended with guessed timestamps or red-green claims.

8. The post-review cleanup removed simulated card-entry fields, moved checkout copy and order placement into focused React modules, and recorded AC-Y1/AC-Y2 as intentional deviations. At that point, manual device checks and final CI evidence were still outstanding; later entries below record the software verification that followed. Physical-device validation remains outside this take-home.
9. The checkout quote/menu and order responsibilities were split into separate application services. Delivery-contract checks were aligned with the no-credential flow, and the final local domain, API, browser, E2E, Production-browser, build, lint, and strict trace checks passed; see `plan-review.md` for counts and environment limits.
10. A further security pass removed inline-style and data-URI allowances from the CSP. The Production browser check now launches the ASP.NET app with an isolated SQLite database, verifies the actual response policy and packaged images, and completes a simulated order; the parent runner removes its temporary database after the host stops.
11. The backend was reorganized into Domain, Application, Contracts, SQLite Infrastructure, and HTTP host projects. Catalog and order-placement workflows now use application-owned ports, settlement/reservation transactions remain behind SQLite adapters, frontend state/presentation/screens were extracted into focused modules, and an architecture-boundary check was added. These boundaries are documented in [ADR-0008](adr/0008-layered-modular-monolith.md) and [ADR-0009](adr/0009-http-contract-boundary.md), and guarded by `scripts/architecture-boundaries.test.mjs`.
12. Follow-up concurrency work added a simultaneous same-key test and a retryable response when SQLite settlement is temporarily locked. The implementation and regression tests are visible in [the concurrent idempotency test](https://github.com/FirasAyari/self-service-checkout/commit/659b402), [the settlement contention fix](https://github.com/FirasAyari/self-service-checkout/commit/4ea7310), and [the lock-release regression](https://github.com/FirasAyari/self-service-checkout/commit/f0568f2).
13. On 2026-10-22, a clean clone of source commit `6e20dcc` followed the README setup, build, tests, browser checks, audits, and startup path. The current evidence is recorded in [the submission matrix](submission-requirements-matrix.md) and [the plan review](plan-review.md). GitHub Actions run [#29](https://github.com/FirasAyari/self-service-checkout/actions/runs/39776458035) passed the backend, frontend/Docker, and browser/Unix-startup jobs on that source commit. This timeline remains a concise retrospective; the commit history and ADRs are the stronger evidence for exact changes and decisions.
