## Source and method

The controlling assignment brief is the user-provided `web_checkout_v0.1.pdf`, supplied outside this repository. It deliberately gives a broad take-home brief rather than a checklist. The detailed rows below operationalize it using [business-rules.md](business-rules.md), [scenarios.md](scenarios.md), and [traceability.md](traceability.md), with scope decisions in [plan-review.md](plan-review.md). `MET` means the focused automated check ran and passed; `PARTIAL` means only part of the stated requirement has software evidence, a deliberate deviation applies, or environment/hardware evidence is unavailable; `MISSING` means no focused automated test proves the scenario. A trace link alone is not counted as test coverage.

Named test links are regenerated and checked against current test declarations by `node scripts/submission-matrix-evidence.mjs`; run it with `--fix` after changing test names or adding coverage. CI verifies the line references and acceptance IDs, while reviewers must still inspect the cited assertions to judge whether they prove the row.
